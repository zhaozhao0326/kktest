# Agent 化工具调用与 Skills 按需加载改造需求

日期：2026-06-01

## 文档定位

本文档描述下一步将聊天应用改造成具备 Agent 能力时需要满足的需求。本文档只描述“需要具备什么能力”和“验收时应看到什么结果”，不描述具体实施阶段、代码改造顺序或技术排期。

## 背景

当前项目已具备原生 tool calling、内置工具、MCP 桥接、MCP 直连、Notion 工具和工具调用日志等基础能力。继续扩展后，应用可以从“角色聊天应用”升级为“角色聊天 + 任务型 Agent”的组合形态。

当前主要问题是：

- MCP 工具 schema 可能在普通聊天中带来较高输入 token 和延迟。
- “模型工具调用”和“后台异步处理”的产品语义需要区分。
- 工具数量增多后，需要按场景和意图加载，而不是每轮暴露全部工具。
- 若未来支持跑命令、改文件、访问 VPS 或云端沙盒，必须建立权限、隔离和审计边界。
- Skills 更适合承载流程知识、任务规范和按需上下文；MCP 更适合承载外部系统连接和可执行动作。两者应组合使用。

## 目标

- 普通聊天保持轻量、稳定、低 token。
- 需要外部能力时，AI 可以按需使用工具，并让用户理解调用范围和风险。
- 支持 Skill-like 的按需加载机制，避免功能说明、工具 schema 和长流程提示常驻主上下文。
- 支持未来扩展到本地 bridge、云端沙盒或 VPS 任务执行，但不允许网页直接获得无限制 shell。
- 保留现有角色聊天、记忆、日程、日记、Notion 和 MCP 能力的兼容性。

## 非目标

- 不要求把当前 Web/PWA 重写成原生 App。
- 不要求普通角色聊天默认具备 Codex/Claude Code 级别的项目操作能力。
- 不要求模型直接持有 SSH 密钥、API 密钥或本地文件系统权限。
- 不要求一次性接入完整外部 Skills 生态。
- 不要求所有 MCP 工具都能在普通聊天中自动暴露。

## 术语

- 普通聊天：以陪伴、角色扮演、轻量问答为主的聊天模式。
- Agent 模式：以完成任务为目标，允许调用工具、查看执行过程、产出结果或变更的模式。
- Tool：模型可调用的结构化动作，例如写日记、创建日程、查 Notion、运行命令。
- MCP：外部工具和数据源的连接层，可暴露 tools、resources 和 prompts。
- Skill：按需加载的流程知识包，包含触发条件、使用规则、上下文说明、工具范围和输出要求。
- Toolset：某个场景下允许暴露给模型的一组工具。
- Bridge：本地或服务端执行环境，负责执行浏览器不能直接完成的动作。
- Sandbox：隔离的命令执行环境，用于云端运行代码、测试或自动化任务。

## 角色与使用场景

### 普通用户

- 希望日常聊天流畅，不因后台工具或 MCP 导致明显变慢。
- 希望 AI 在明确需要时帮忙记忆、写日记、建日程、查资料。
- 希望知道 AI 是否调用了外部工具，以及调用是否成功。

### 高级用户

- 希望配置 MCP、Notion、云端服务或本地 bridge。
- 希望不同角色、群聊或功能页使用不同工具范围。
- 希望控制 token 成本、工具权限和调用日志。

### 开发者用户

- 希望未来可以让 Agent 读写项目、运行命令、查看 diff、跑测试。
- 希望命令执行环境有目录限制、超时、审计和确认机制。
- 希望可选择本地 bridge 或云端 sandbox。

## 功能需求

### FR-001 普通聊天默认轻量

普通聊天在没有明确工具意图时，不应携带 MCP 工具 schema 或大量工具说明。

验收标准：

- 普通消息不命中工具意图时，请求 payload 不包含 `tools`。
- 普通聊天不因全局启用 MCP 而自动暴露所有 MCP 工具。
- 普通聊天的输入 token 不应因工具系统显著增长。

### FR-002 模型工具调用与后台异步处理分离

应用必须区分“模型工具调用”和“后台异步处理”。

验收标准：

- 用户界面不应把 tool calling 描述成后台异步优化。
- 后台记忆提取、总结、缓存刷新等任务不应默认污染主聊天请求。
- 模型工具调用开启时，需提示可能增加输入 token、延迟和外部动作风险。

### FR-003 工具按意图暴露

工具必须支持按用户意图、当前页面、联系人配置和场景裁剪。

验收标准：

- “记住/别忘”类请求只暴露记忆相关工具。
- “写日记/补记日记”类请求只暴露日记相关工具。
- “提醒/日程/待办”类请求只暴露日程相关工具。
- “查 Notion/搜文档/工作区”类请求只暴露相关 MCP/Notion 检索工具。
- 单轮暴露工具数量必须有上限。

### FR-004 Skill Registry

应用需要维护 Skill 注册表，用于描述可按需加载的能力包。

每个 Skill 至少包含：

- 唯一 ID。
- 名称。
- 简短摘要。
- 触发条件。
- 适用页面或场景。
- 允许使用的工具或 Toolset。
- 风险等级。
- 是否需要用户确认。
- 详细说明的加载入口。

验收标准：

- 未命中 Skill 时，不加载该 Skill 的详细说明。
- 命中 Skill 后，只加载该 Skill 所需的最小上下文。
- Skill 摘要可用于本地路由，不要求每次都交给模型判断。

### FR-005 Skills 与 MCP 组合使用

Skills 不替代 MCP；Skills 负责流程和上下文，MCP 负责外部连接和动作。

验收标准：

- Notion 类能力可以由 Skill 描述“何时查、如何查、如何总结”，由 MCP/Notion 工具执行查询。
- 编程类能力可以由 Skill 描述“如何读项目、如何改文件、如何验证”，由 bridge/sandbox 工具执行文件和命令操作。
- 每个 Skill 必须声明可用工具范围，不能默认继承全部 MCP 工具。

### FR-006 MCP 服务器选择语义清晰

联系人、群聊和全局配置中的 MCP 选择必须避免“留空就是全部启用”的隐性高成本行为。

验收标准：

- UI 需要区分“不使用 MCP”“跟随全局”“指定服务器”。
- 新建联系人默认不应自动继承全部 MCP 工具。
- 用户可以看到某个会话实际会使用哪些 MCP 服务器。
- 用户可以看到已发现工具数量和最近检测状态。

### FR-007 工具 schema 成本可控

工具定义需要进行数量控制和说明压缩，避免 MCP schema 过大。

验收标准：

- 工具总数有硬上限。
- MCP 工具 description 和参数 schema 应尽量短。
- 对复杂 MCP 服务器，必须支持只允许部分工具进入候选集。
- 请求统计中需要记录本次工具数量和工具 schema 估算成本。

### FR-008 工具调用日志

用户需要能查看 AI 调用了什么工具、传入了什么安全摘要、执行结果是什么。

验收标准：

- 工具调用日志能区分内置工具、MCP 工具、本地 bridge 工具和云端 sandbox 工具。
- 日志包含工具名称、来源、执行状态、耗时和错误摘要。
- 高风险工具的参数展示需要脱敏。
- 普通聊天中可选择隐藏或展示工具调用卡片。

### FR-009 权限分级

工具必须按风险分级，并根据风险决定是否需要确认。

风险等级至少包括：

- 只读：查询、搜索、读取非敏感上下文。
- 本地写入：写日记、写记忆、创建日程、修改应用内数据。
- 外部写入：写 Notion、发请求、改第三方系统数据。
- 文件写入：创建、修改、删除工作区文件。
- 命令执行：运行 shell、安装依赖、启动服务、执行测试。
- 凭据相关：读取、传递或使用密钥、token、SSH 凭据。

验收标准：

- 高风险工具默认需要用户确认。
- 用户可以允许一次、拒绝、或对特定工具和范围记住授权。
- 权限授权必须绑定工具、范围和上下文，不允许泛化为无限制授权。

### FR-010 命令执行不能由网页直接完成

网页端不得直接执行本地命令。命令执行必须通过受控执行环境完成。

验收标准：

- 浏览器前端只发起工具请求，不直接拥有 shell 权限。
- 本地命令必须通过本地 bridge 或桌面壳内受控服务执行。
- 云端命令必须通过后端创建或选择隔离 sandbox 执行。
- 所有命令执行都需要工作目录限制、超时、输出长度限制和审计日志。

### FR-011 本地 Bridge 执行要求

本地 bridge 用于个人或开发者场景，提供类似 Codex/Claude Code 的本地项目操作能力。

验收标准：

- bridge 只能访问用户显式授权的工作目录。
- bridge 不应默认暴露整个磁盘。
- bridge 提供文件读写、命令执行、git diff、测试运行等受控工具。
- 写文件、删除文件、安装依赖、执行外部网络命令等高风险动作需要确认。
- bridge 需要返回结构化结果，而不是只返回原始终端输出。

### FR-012 云端 Sandbox/VPS 执行要求

云端执行用于多人产品或远程任务场景。

验收标准：

- 每个任务或用户工作区必须隔离。
- AI 不应直接持有 SSH 私钥。
- 若接入用户 VPS，推荐通过用户安装的 agent 服务暴露受控 API，而不是让模型直接 SSH。
- sandbox 需要支持超时、资源配额、网络限制、日志留存和销毁策略。
- 需要明确用户数据、代码、日志和产物的保存周期。

### FR-013 Agent 模式 UI

Agent 模式需要区别于普通聊天，展示任务进度、工具调用和结果。

验收标准：

- 用户可以看到 Agent 正在执行的任务状态。
- 用户可以查看步骤列表、工具调用、命令输出摘要和最终产物。
- 失败时能看到失败原因和可重试动作。
- 涉及文件修改时，应展示变更摘要或 diff。
- 普通角色聊天不应被强制转换成任务执行界面。

### FR-014 工具结果回传控制

工具结果不能无控制地全部塞回模型上下文。

验收标准：

- 大输出必须截断、摘要或分页。
- 命令输出、搜索结果、文件内容需要有最大 token/字符限制。
- 结构化结果优先于长文本结果。
- 用户可查看完整原始日志，但模型默认只接收必要摘要。

### FR-015 Token 与成本观测

应用需要解释工具和 Skills 对 token 的影响。

验收标准：

- 请求记录包含 `toolsCount`、MCP server 数、Skill ID、工具 schema 估算 token、消息估算 token。
- token 胶囊或调试日志可以区分普通提示、记忆、历史消息、功能规则、Skill 上下文、工具 schema。
- 当预计 token 超过阈值时，应用需要提示或自动降级。

### FR-016 兼容现有数据

改造不得破坏现有聊天、角色、记忆、日记、日程、MCP 配置和 Notion 配置。

验收标准：

- 旧数据可以正常加载。
- 缺失新字段时有默认值。
- 已配置 MCP 的用户不会丢失配置。
- 行为语义变化需要在 UI 中明确展示，避免用户误以为配置丢失。

### FR-017 调试与开发者可见性

开发者需要能判断一次回复为什么加载了某个 Skill、为什么暴露了某些工具。

验收标准：

- 调试日志记录 Skill 命中原因。
- 调试日志记录工具筛选原因。
- 调试日志记录 MCP 发现、裁剪、调用错误。
- 调试日志能关联单次请求的 traceId。

## 非功能需求

### NFR-001 安全

- 默认最小权限。
- 敏感字段脱敏。
- 外部写入和命令执行必须可审计。
- 不允许模型绕过权限确认直接执行高风险动作。

### NFR-002 性能

- 普通聊天不得因 Skills/MCP 改造明显增加首 token 延迟。
- 工具发现结果需要缓存，但缓存不得导致权限变更后继续暴露旧工具。
- 大型 MCP 工具集必须支持裁剪。

### NFR-003 可维护性

- Skill、Tool、Toolset、MCP 服务器配置需要有清晰边界。
- 新增 Skill 不应要求修改多个聊天 orchestrator。
- 新增工具应能声明风险等级、参数 schema、执行器和日志展示方式。

### NFR-004 可解释性

- 用户应能理解“为什么这次用了工具”。
- 用户应能理解“为什么这次成本更高”。
- 开发者应能从日志复盘一次 Agent 执行。

## 数据与配置需求

### Skill 数据

Skill 配置至少需要支持：

- `id`
- `name`
- `summary`
- `triggers`
- `scopes`
- `toolsetIds`
- `riskLevel`
- `requiresConfirmation`
- `instructionRef`
- `enabled`

### Tool 数据

Tool 定义至少需要支持：

- `name`
- `description`
- `parameters`
- `source`
- `sourceLabel`
- `riskLevel`
- `requiresConfirmation`
- `executor`
- `displayName`
- `allowedScopes`

### Toolset 数据

Toolset 至少需要支持：

- `id`
- `name`
- `toolNames`
- `maxTools`
- `mcpServerIds`
- `enabled`

### 会话级配置

联系人或群聊至少需要支持：

- 是否允许模型工具调用。
- MCP 使用语义：不使用、跟随全局、指定服务器。
- 允许的 Skills。
- 允许的 Toolsets。
- 高风险工具确认偏好。

## 验收指标

- 普通聊天无工具意图时，`toolsCount = 0`。
- 普通聊天无工具意图时，不加载详细 Skill 指令。
- 明确工具意图时，只加载相关 Skill 和少量相关工具。
- 单轮暴露工具数不超过配置上限。
- 全局 MCP 启用但会话选择“不使用 MCP”时，不发现也不暴露 MCP 工具。
- 高风险动作必须出现确认流程。
- 命令执行必须通过 bridge 或 sandbox，不从网页直接执行。
- 工具结果过大时，模型只接收摘要或截断内容。
- 调试日志可以追踪 Skill 命中、工具筛选、工具调用和最终回复。

## 风险与约束

- MCP 工具越多，schema 成本越高；必须默认保守。
- Skills 会降低常驻 token，但如果命中后加载过多说明，也可能重新变贵。
- 命令执行能力会显著提高安全风险，必须先有权限和隔离需求。
- 云端 sandbox 涉及成本、滥用、数据隔离和日志留存，需要产品侧明确边界。
- 本地 bridge 适合个人开发者，但对普通用户有安装和信任门槛。

## 待澄清需求

- Agent 模式是否作为独立入口，还是嵌入现有角色聊天。
- 是否需要支持多人共享云端 workspace。
- 是否需要支持用户自带 VPS。
- 是否需要支持文件 diff 审批后再写入。
- 是否需要对不同用户等级限制工具数量、sandbox 时长或命令权限。
